# Моя прибыль

Русское приложение для личного учёта доходов, расходов и месячных целей. React + TypeScript + Vite, Tailwind CSS, Dexie/IndexedDB, Recharts и vite-plugin-pwa. Нет регистрации, серверной базы, платных API или обязательной подписки. Первоначально база пустая: никакие демонстрационные суммы не подменяют ваши данные.

## Запуск на Windows

1. Установите Node.js 24 LTS.
2. Откройте PowerShell в папке проекта.
3. Выполните `npm ci`, затем `npm run dev`.
4. Откройте адрес, который появится в терминале (обычно http://localhost:5173).

Проверки: `npm run typecheck`, `npm run lint`, `npm test`, `npm run build`. Браузерные тесты: `npx playwright test` (используют установленный Microsoft Edge). Для просмотра готовой сборки: `npm run preview`. Полноценный офлайн-режим проверяется на готовой сборке, а не на сервере разработки. HTTP localhost подходит для проверки на этом компьютере; для iPhone нужен опубликованный HTTPS-адрес.

## Бесплатная публикация через GitHub Pages

1. Создайте бесплатную учётную запись GitHub и публичный репозиторий, например `moya-pribyl`. Публичным будет код; финансовые данные остаются в браузере.
2. Загрузите файлы проекта в ветку `main`. Не загружайте `node_modules`, `dist`, резервные копии и личные финансовые файлы. Проще использовать GitHub Desktop: Add local repository → Create repository → Publish repository.
3. В репозитории откройте Settings → Pages → Source → GitHub Actions.
4. Откройте Actions → Publish PWA → Run workflow. Если загрузка в `main` уже запустила сборку, дождитесь её завершения.
5. Адрес появится в Settings → Pages и в результате Deploy. Обычно это `https://ВАШЕ-ИМЯ.github.io/moya-pribyl/`.

Workflow автоматически задаёт путь `/имя-репозитория/`, запускает проверки и публикует `dist`. Для репозитория `ВАШЕ-ИМЯ.github.io` замените BASE_PATH в workflow на `/`. Для собственного домена также нужен `/`. Публикация из этой рабочей папки пока не выполнялась.

Альтернатива: Cloudflare Pages, команда сборки `npm run build`, выходная папка `dist`, Node.js 24, BASE_PATH `/`. Финансовым данным не нужна облачная база.

## Установка на iPhone

1. Откройте опубликованный HTTPS-адрес в Safari.
2. Дождитесь сообщения «Готово к работе без интернета». Откройте Аналитику один раз для проверки загрузки графиков.
3. Нажмите «Поделиться» → «На экран Домой» → «Добавить».
4. Запустите приложение через новую иконку. Добавьте тестовую операцию, закройте и откройте приложение, убедитесь, что она сохранилась.
5. Включите авиарежим и повторите проверку. Удалите тестовую операцию после проверки.

При обновлении приложение предлагает кнопку «Обновить». Она показывается после закрытия формы, чтобы не сбрасывать незавершённый ввод. Обновления интерфейса не очищают IndexedDB. Перед важным обновлением сохраните JSON-копию. Не удаляйте сайт, его данные или установленное приложение ради обновления.

## Как пользоваться

- На Главной нажмите «Доход» или «Расход», заполните сумму, дату и категорию. Комментарий необязателен. Допускаются запятая или точка и до двух знаков копеек.
- Нажмите на операцию для изменения или удаления с подтверждением.
- История показывает суммы по дням. Нажмите строку, чтобы открыть все операции этого дня.
- Стрелки или выбор месяца позволяют открыть прошлые месяцы и годы.
- Нажмите на карандаш у цели. Цель хранится отдельно для каждого месяца и относится к чистой прибыли.
- Аналитика показывает ежедневную прибыль, расходы по категориям, доходные дни, лучший день, сравнение месяцев и цели.
- Настройки позволяют изменить тему, создать или переименовать категорию и убрать её в архив. Архив не удаляет операции.

Сегодня всегда относится к текущей локальной дате устройства, даже если в обзоре выбран прошлый месяц. Средняя прибыль рассчитывается только по дням с доходами и учитывает все расходы этих дней. Лучший день выбирается среди дней с операциями. Отсутствие цели не считается провалом.

## Резервная копия

Откройте Настройки → «Сохранить JSON». На iPhone найдите загрузку в Safari, откройте файл → «Поделиться» → «Сохранить в Файлы». Сохраните в iCloud Drive или другой папке вне данных сайта. Делайте это регулярно и перед сменой устройства.

JSON содержит операции, категории, цели, версию формата и дату создания. CSV предназначен для Excel и не восстанавливает базу. CSV использует UTF-8, разделитель `;`, запятую для копеек и защиту текстовых полей от формул Excel.

Для восстановления выберите JSON в Настройках, проверьте дату и число записей, затем подтвердите замену. Текущие данные полностью заменятся: сначала сохраните их отдельной копией. Повторный импорт не создаёт дублей. При повреждённом файле или ошибке записи вся транзакция отменяется.

Резервная копия не зашифрована. Храните её там, где доступ есть только у вас. Локальное хранилище не гарантирует защиту от удаления системой, пользователем или очисткой Safari. Запрос постоянного хранения может быть отклонён браузером.

## Архитектура и развитие

- `src/models.ts` — модели операции, категории и цели.
- `src/finance.ts` — чистые функции расчётов, дат и сумм.
- `src/db.ts` — версия 1 базы, индексы, валидация и атомарный импорт.
- `src/App.tsx` — интерфейс и формы; `src/Analytics.tsx` загружается отдельно.
- `src/style.css` — общие монохромные токены, темы, safe area и reduced motion.

Деньги — положительные целые копейки, тип операции определяет знак. Лимит одной операции/цели — 10 млрд ₽. Даты — локальные YYYY-MM-DD. Уникальный индекс `[year+month]` предотвращает повторные цели. Новые версии схемы добавляйте через `db.version(2).stores(...).upgrade(...)`, сохраняя существующие таблицы. Накопительные счета и синхронизацию можно добавить отдельными моделями и сервисами; они не реализованы в версии 1.

## Ограничения

Нет синхронизации между устройствами: переносите JSON вручную. Другой домен, профиль или браузер имеет отдельную базу. Рекомендация отложить 10% информационная и не проверяет обязательные платежи. Приложение не выполняет переводы.

Фактические установка на iPhone, экранная клавиатура Safari и сохранение системой iOS требуют проверки на устройстве. Это не заменяется тестами на компьютере. Первая загрузка требует интернет. Большие базы целиком читаются для аналитики; при существенно больших объёмах потребуется постраничная загрузка. Приложение не имеет парольной блокировки и использует защиту самого устройства.

Браузерные сценарии проверяют добавление дохода/расхода с копейками, цель, редактирование, удаление, сохранение после перезагрузки, экспорт JSON, подтверждённый импорт, тёмную тему и запуск без сети. TypeScript, ESLint и production-сборка проходят. После обновления инструментов npm audit сообщает 0 известных уязвимостей. Проверки браузера выполнены в Edge с мобильным размером экрана, а не в Safari на физическом iPhone.

Для PWA обновления используется режим запроса пользователю, рекомендованный [vite-plugin-pwa для приложений с формами](https://vite-pwa-org.netlify.app/guide/auto-update). Для восстановления используется [транзакция Dexie](https://dexie.org/docs/Dexie/Dexie.transaction%28%29), позволяющая откатить все изменения при ошибке.
